# P4 真实暂停：行为合同与实施切片

本切片属于已授权的 P0–P6 原生迁移，不重开或重置 UI 独立审查重试预算。当前总体迁移与发行验收仍未完成。

## 目标与边界

- 暂停是会话内运行状态，不改写 `BackgroundIndexingEnabled`、目录授权、索引时段、模型 profile 或数据库格式。
- 状态为 `Running`（允许索引）、`Pausing`（已拒绝新工作、等待在途工作取消收敛）、`Paused`（无在途工作）。只有实际收敛后才能显示“已暂停”。搜索仍可使用。
- 暂停取消当前索引并拒绝/取消已排队和新提交的索引；文件状态保持实际 pending/partial/failed/done，不标记虚假完成，不触发删除对账。
- 恢复后允许新索引；若用户原已启用后台监控，则主动请求一次完整协调扫描。不自动恢复已取消的手动请求，不擅自开启后台许可。
- 暂停/恢复、设置变更与退出不得形成锁顺序环；暂停期间文件监听仍可保持连接，但不得产生索引写入、模型加载或错误自旋。

## 接口

Core 新增 `IndexingControlState { Running, Pausing, Paused }`；`EngineStatus` 末尾增加可选 `IndexingState`，默认 Running，避免破坏现有状态构造调用。

`IDesktopBackend.SetIndexingPausedAsync(bool paused, CancellationToken)` 为真实控制接口。UI 只有调用成功/状态探针确认后才更新暂停状态；失败显示真实错误。CLI 只读操作仍禁用后台协调。

## 关键失败模式与负向断言

1. 预取消调用：不修改状态、不创建模型或数据工作。
2. 模型/解析依赖不响应取消：控制调用有界失败，保留 Pausing，不伪装 Paused；仍禁止新索引。
3. 暂停与恢复/重复点击并发：串行化状态转移，旧队列不得越过暂停代次进入新状态。
4. 暂停与退出并发：退出取消优先，完整释放 watcher、仓库和模型；不得遗留任务或恢复索引。
5. 暂停期间设置保存：保留暂停，不恢复后台扫描；实际配置 CAS/授权规则不变。
6. 暂停造成的取消不是数据库/模型失败，后台协调不得因此永久 fault 或反复记录假错误。
7. 恢复不改变用户后台开关；未启用后台时不得自动扫描。

## 验证

- 控制器：单工作互斥、在途和排队取消、暂停态拒绝、幂等、恢复、不合作依赖/超时、并发退出。
- 真实 Backend：只用任务合成目录和显式 fake host，证明索引取消后停止写入、暂停态搜索可用、恢复后可以重新索引；不使用个人目录或真实模型。
- UI：fake backend 可用于记录真实控制调用和失败反馈；不得只切换布尔值。主窗口和托盘保持一致，读取实际状态。
- 集成：Core/Infrastructure/App 构建、受影响测试、任务目录真实 native smoke；模型/像素/安装验收仍单独保留未知。
