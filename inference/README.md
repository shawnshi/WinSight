## Bounded source navigation — non-GUI source accepted

Explicit backend source operations use a stored source SHA-256 and current authorization checks; legacy/mismatched source identity permits indexed text only, not raster/regions/exact navigation. `open-office-location` supports bounded DOCX body paragraphs, XLSX sheet/A1 rectangles and PPTX slide ordinals. Word fields and Excel formulas/defined names/linked data are conservatively rejected; this is not a general Office sandbox or full-document mapping guarantee.

PPT navigation opens the requested original source read-only, unlike whole-slide indexing, which opens a task copy. It requires an idle-exclusive installed PowerPoint and verifies its owned PID/frame/application path, read-only source and selected slide before handing the window to the user. Successful natural worker exit cannot be hidden by late cancellation; settlement, bounded strict pipe drain and strict result validation remain required. Unknown outcomes retain material and must not be automatically replayed. Receipt-before-handoff can conservatively retain a failed attempt; that P2 boundary is accepted, not repaired.

The bounded non-GUI source subset and retained P2s were owner-accepted after final independent review. GUI preview, OCR overlay and keyboard candidates are excluded. See [public scope and retained risks](../docs/native-migration/source-integration-status.md); this is not install or Release approval.

Windows.Data.Pdf destinations are DIPs: a small measurement render and canonical re-encode avoid monitor-scale-dependent dimensions. Only this render operation adds a512MiB aggregate Job commit limit; this is not a credential/network/OS sandbox.
